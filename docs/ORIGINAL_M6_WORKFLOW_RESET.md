# Original M6 Workflow Reset Contract

Status: **active governing workflow for Practice / Pro reference-driven editing**

Authority: `EditFlow_2.0_M6_Professional_Effects_Transitions_Roadmap_No_Hours.pdf`.

## Purpose

This reset restores the original M6 production loop as the governing edit workflow while preserving all later capabilities as tools. The reset is a workflow/controller reset, not a capability rollback.

The original M6 north star remains unchanged: an effect is correct only when rendered visual behavior demonstrates the defining characteristics of the professional reference. Successful AE commands, valid recipes, or plausible constructions are not fidelity proof.

## Governing reference-driven loop

Practice and any reference-driven production path must follow this order:

`RAW FOOTAGE + PROFESSIONAL REFERENCE`
-> `SCENE UNDERSTANDING + EDITORIAL DECISION`
-> `REFERENCE EFFECT DETECTION`
-> `DENSE FRAME EVIDENCE`
-> `EFFECT ANATOMY + TRANSITION DNA`
-> `TUTORIAL / LEARNED CAUSAL KNOWLEDGE`
-> `LAYER / CONSTRUCTION HYPOTHESIS`
-> `CAPABILITY MAPPING + NEW EFFECT SYNTHESIS`
-> `RECIPE COMPILER -> VIRTUAL AE -> REAL AE`
-> `LOCAL RENDER`
-> `REFERENCE <-> RENDER FIDELITY COMPARATOR`
-> `VISUAL ERROR DIAGNOSIS`
-> `AUTOMATIC CORRECTION LOOP`
-> `FIDELITY GATE`
-> `FINAL EDIT`.

For difficult/high-risk reference effects, reference evidence is authoritative. A retained learned graph may inform hypotheses and adaptation, but it must not bypass fresh reference anatomy, synthesis, rendered comparison, or bounded correction.

## Advanced systems remain available

The following later systems remain part of EditFlow's tool surface and may be invoked when the original M6 loop needs them:

- Edit Type knowledge and experience memory.
- Tutorial causal compiler and Tutorial Drive research.
- Dense real-media source indexing and exact scene binding.
- Subject identity memory and cross-source verification.
- SAM 3.1, Roto Brush, tracked masks, subject isolation, and object-aware proof.
- Optical-flow, temporal rewind, speed remap, masks, tracking, displacement, native/adaptive AE capabilities.
- Retained truth suites, held-out certification, benchmark evidence, and anti-shortcut verification.
- Current-AE transactional execution, warm CEP paths, Desktop Commander recovery, and local fast runtime.
- Automatic correction memory and unknown-effect synthesis.

These are supporting capabilities. None may create a parallel governing edit loop that competes with the original M6 reference-first process.

## Continuity is mandatory

A Practice session is one durable unit of work even when many ChatGPT conversations are used.

A new ChatGPT controller must:

1. Discover the existing PENDING/RUNNING assignment before creating anything new.
2. Read the retained assignment events, artifacts, current AE state, and latest completed checkpoint.
3. Reclaim/resume the same assignment.
4. Continue at the first incomplete or invalidated step.
5. Re-run earlier work only when inputs changed or retained proof explicitly shows that checkpoint is invalid.
6. Treat infrastructure failures as pauses: repair the connection, verify readiness, then resume the same assignment.

A new chat is never a reason to restart reference analysis, source matching, baseline assembly, effect reconstruction, or rendering.

## Efficiency rules

- Reuse the same matched scene set and content-locked baseline.
- Prefer bounded local effect-window renders before a full-edit render.
- Preserve the best retained attempt and correction state.
- Do not re-prove unchanged AE capabilities.
- Do not ingest or place the full raw movie into AE after the required source ranges are identified.
- One meaningful revision should produce one new comparison checkpoint, not a duplicate end-to-end restart.
- Repair blocking bugs immediately, then resume from the prior checkpoint.

## Reset boundary

This reset intentionally changes the controller behavior introduced after original M6:

- HIGH-risk/reference-driven M6 no longer starts from a retained learned graph.
- Active Practice assignments are resumable across ChatGPT handoffs.
- "Next assignment" returns active RUNNING work before new PENDING work.
- Repeated Practice start requests return the active Practice run rather than creating or encouraging a duplicate.
- Advanced Practice/Pro systems remain callable tools and proof infrastructure.

## Definition of success

The reset is working when repeated "Continue the Practice session" requests across different ChatGPT conversations advance one retained edit toward completion instead of spawning repeated analysis/build/render cycles, while the edit itself still has access to every advanced capability accumulated after M6.
