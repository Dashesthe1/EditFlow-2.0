# M2 autonomous workstation loop

This path exists so ChatGPT can patch the greenfield EditFlow 2.0 repository, let the target Windows/After Effects workstation execute the bounded M2 proof, inspect uploaded evidence, and iterate without using a person as a PowerShell relay.

## Safety boundary

- Workflow trigger is restricted to pushes on `workstation/m2-live` plus explicit manual dispatch.
- The runner must use the dedicated label `editflow-ae-shadow-m2`.
- The workflow has repository `contents: read` permission only.
- No pull-request trigger is accepted for the self-hosted workstation.
- The workstation script is pinned to `C:\Program Files\Adobe\Adobe After Effects 2025\Support Files\AfterFX.exe` and product version prefix `25.6.6`.
- If another After Effects installation is running, the workflow fails closed instead of closing or targeting it.
- The script installs only the checked-in EditFlow CEP extension, preserving the existing local authentication token.
- A read-only CEP smoke runs before the bounded real-AE acceptance proof.
- The real-AE proof remains temporary, does not save/replace the project, and keeps the M2 general Adobe-write gate disabled.
- Diagnostic collection is bounded to known EditFlow proof/config/extension paths and redacts the authentication token.

## One-time runner registration

The GitHub runner must run **interactively in the logged-in Windows desktop session**, not as a Windows service, because After Effects and CEP need access to the interactive desktop.

1. In GitHub open this repository, then **Settings → Actions → Runners → New self-hosted runner**.
2. Select **Windows** and **x64**.
3. In an ordinary PowerShell window under the same Windows user that runs After Effects, execute GitHub's displayed download/extract commands.
4. Run GitHub's displayed `config.cmd` command and add the custom label `editflow-ae-shadow-m2`. Keep the default `self-hosted`, `Windows`, and `X64` labels.
5. Do **not** install the runner as a service. Start it with `run.cmd` in that logged-in desktop session and leave that runner window open during the M2 development loop.

The GitHub registration token is short-lived and is generated by GitHub's runner setup page. It is not committed to this repository and should not be shared in chat.

## One-time bridge activation for hot reload

After the hot-reload bridge change lands on `main`, update the local clone once, reinstall the CEP bridge once, restart After Effects 2025 once, open a blank unsaved project, and open **Window → Extensions → EditFlow 2.0 Bridge**. After that, each new broker registration reloads the checked-in `editflow_host_current.jsx` from the installed extension, so host-side fixes can normally be picked up without restarting After Effects.

A future change to the already-running `client/bridge.js` itself may still require a panel/After Effects restart. Host-side adapter changes do not.

## Autonomous iteration contract

After the runner is online, ChatGPT uses the `workstation/m2-live` branch as the test branch. Each push produces one serialized workstation run. The run uploads:

- read-only CEP smoke evidence;
- bounded real-AE acceptance evidence;
- render lifecycle evidence when present;
- redacted workstation diagnostics.

ChatGPT can inspect those GitHub Actions artifacts/logs, patch the branch, and push another iteration. Only proven fixes are promoted back to `main`.
